## 通用约定

### HTTP 状态码约定

所有客户端接口业务错误**始终返回 HTTP status 200**。客户端通过 JSON body 中的 `code` 字段区分业务结果，无需关注 HTTP 状态码。

### 请求头

| Header          | 必填 | 说明                                                                                    |
|-----------------|------|-----------------------------------------------------------------------------------------|
| `Content-Type`  | 是   | `application/json`（默认）或 `application/x-protobuf` / `application/protobuf`（可选） |
| `Authorization` | 是   | `Bearer <token>`，Token 由登录接口获取                                                  |

> 响应格式与请求 `Content-Type` 保持一致：发 JSON 收 JSON，发 protobuf 收 protobuf。

### 序列化格式

服务端统一根据请求的 `Content-Type` 决定上下行的序列化格式，请求与响应格式保持一致。

| Content-Type                                              | 请求解析方式      | 响应序列化方式  |
|-----------------------------------------------------------|-------------------|-----------------|
| `application/json`（或不填）                              | JSON              | JSON            |
| `application/x-protobuf` / `application/protobuf`        | Protobuf 二进制   | Protobuf 二进制 |

Proto 定义见 `pb/cs.proto`（`FriendService`，C# 命名空间为 `Cspb`），相关消息：`FriendApplyReq`、`FriendApplyResp`、`FriendApplyHandleReq`、`FriendApplyHandleResp`、`FriendApplyCancelReq`、`FriendApplyCancelResp`、`FriendApplyListReq`、`FriendApplyListResp`、`FriendListReq`、`FriendListResp`、`FriendRankReq`、`FriendRankResp`、`FriendDeleteReq`、`FriendDeleteResp`、`ErrorResp`。

> **错误响应的 protobuf 兼容性**：所有 `*Resp` 消息的前两个字段（tag 1 = `code`，tag 2 = `message`）与 `ErrorResp` 保持一致，客户端可直接用具体 `*Resp` 类型解析错误响应，无需额外处理。

### 统一响应结构（JSON 模式）

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

| 字段      | 类型   | 说明                                     |
|-----------|--------|------------------------------------------|
| `code`    | int    | `0` 表示成功，非 `0` 为业务错误码       |
| `message` | string | 结果描述，成功时为 `"ok"`                |
| `data`    | object | 成功时的业务数据，失败时为 `null` 或省略 |

> 例外：`POST /api/friend/apply` 响应无 `data` 包装（见[发送好友申请](#发送好友申请)）。

### 时间戳

所有时间戳（`createdAt`）均为 **Unix 毫秒**。

### 玩家身份

所有接口的操作者身份一律取自 `Authorization` Token 解析出的玩家 ID，**不接受客户端在请求体中伪造**。

## 好友业务规则

### 好友关系存储

好友关系采用**双向冗余存储**：A 与 B 互为好友时，数据库同时保存 A→B 与 B→A 两条记录，好友列表与好友关系判断均为单向查询。

### 申请记录语义

好友申请为**单向记录**（`applyUid` → `targetUid`）：

- **记录存在即表示有一笔待处理申请**，不存储申请状态。
- 同意 / 拒绝 / 撤销后，申请记录**立即删除**，不保留历史。
- 同一方向（`applyUid` → `targetUid`）同时**最多存在一条申请**（数据库唯一索引保证）。
- 客户端判断申请状态的方式：申请出现在收到的/发出的申请列表中即为待处理；处理（同意/拒绝/撤销）后记录消失。

### 发送申请规则

发送申请时服务端依次校验：

1. 不能添加**自己**为好友 → 错误 `2430`；
2. 目标玩家必须**存在** → 错误 `2432`；
3. 目标已经是好友 → 错误 `2431`；
4. **对方已向自己发送申请**（存在反向记录）→ 不创建新申请，错误 `2437`，客户端应提示"对方已向你发送申请"，引导去[收到的申请列表](#收到的申请列表)处理。
5. 本人好友数已达上限（最多 **100** 个）→ 错误 `2438`，不创建申请（发送申请时先校验，同意申请时还会校验双方）。

重复向同一玩家发送申请（同方向申请记录已存在）时，服务端返回错误 `2434`（`apply already pending`），不重复创建。

### 同意/拒绝规则

- 仅**记录存在**的申请可被同意/拒绝/撤销；同意/拒绝/撤销即删除申请记录，记录不存在（从未申请或已被处理）→ 错误 `2435`。
- 同意后，服务端在事务内删除申请记录并写入**双向好友关系**，自动补齐历史单向脏数据（幂等 Upsert）。
- **好友数量上限**：同意前校验被同意方与申请方的好友数（最多各 **100** 个），任一方已满员 → 错误 `2438`，不建立好友关系。
- 申请被处理后，同方向可再次发送新申请（创建新的申请记录）。

### 删除好友规则

- 删除好友在事务内**双向删除**好友关系，保证不出现"只删除一侧"的脏数据。
- 删除**不影响**好友申请记录；删除后双方可重新发送申请。

### 分页规则

好友列表与申请列表统一采用**位置分页**（非 keyset），参数为 `start` / `end`：

- `start` / `end` 为**从 1 开始的闭区间**，`(1,20)` 表示查询前 20 条；
- `start` 缺省为 `1`；`end` 缺省为 `start + 19`（即默认每页 20 条）；`end < start` 时按默认规则重置；
- 单页数量上限 **50**，超出时截断；
- `start` 最大有效值为 **101**（对应 `skip` 上限 100，防止深分页拖垮数据库），超出时服务端截断为 101；
- 排序为**创建时间倒序**（新记录在前，`createdAt` 不可变，翻页期间状态迁移不影响记录位置）；
- 响应返回 `hasMore` 字段标识是否还有下一页。

> 幽灵过滤：好友/申请列表会过滤掉**已不存在的玩家**（如已注销）。`hasMore` 以数据库分页结果为准，即使本页末条被过滤，`hasMore` 仍可能为 `true`，客户端应继续翻页直至 `hasMore=false`。

## 发送好友申请

### `POST /api/friend/apply`

向指定玩家发送好友申请。同方向申请记录已存在时返回 `2434`，不重复创建。

#### 请求体

```json
{
  "targetUid": 100002
}
```

| 字段        | 类型  | 必填 | 说明           |
|-------------|-------|------|----------------|
| `targetUid` | int64 | 是   | 被申请人玩家 ID |

#### 成功响应

```json
{
  "code": 0,
  "message": "ok"
}
```

> 注意：本接口响应**无 `data` 包装**，成功仅返回 `code` 与 `message`。

#### 错误响应

| 业务错误码 | message                                     | 说明                                                 |
|------------|---------------------------------------------|------------------------------------------------------|
| `2400`     | `targetUid is required`                     | 缺少 `targetUid` 或小于等于 0                        |
| `2401`     | `missing authorization token`               | 未携带有效 Token，需重新登录                         |
| `2430`     | `cannot add yourself as friend`             | 不能添加自己为好友                                   |
| `2431`     | `already friends`                           | 目标已经是好友                                       |
| `2432`     | `target player not found`                   | 目标玩家不存在                                       |
| `2434`     | `apply already pending`                     | 同方向已存在申请（重复申请或并发冲突）               |
| `2437`     | `you already have an apply from this player` | 对方已向你发送申请，请在收到的申请列表中处理          |
| `2438`     | `friend count limit exceeded`                | 好友数量已达上限（最多 100 个）                    |
| `2440`     | `friend operation failed`                   | 好友操作失败（如数据库异常）                     |
| `2500`     | `internal server error`                     | 服务端内部错误                                       |

## 同意/拒绝好友申请

### `POST /api/friend/apply/handle`

处理**收到**的申请（当前登录玩家必须是申请记录中的被申请人 `targetUid`）。同意/拒绝即删除申请记录，同意后自动建立双向好友关系。

#### 请求体

```json
{
  "applyUid": 100001,
  "accept": true
}
```

| 字段       | 类型  | 必填 | 说明                                          |
|------------|-------|------|-----------------------------------------------|
| `applyUid` | int64 | 是   | 申请人玩家 ID                                 |
| `accept`   | bool  | 是   | 处理动作：`true`=同意，`false`=拒绝（缺省 false 即拒绝） |

#### 成功响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "accept": true
  }
}
```

| 字段     | 类型 | 说明                              |
|----------|------|-----------------------------------|
| `accept` | bool | 实际处理动作：`true`=已同意，`false`=已拒绝 |

> 并发说明：同意/拒绝通过事务内删除申请记录实现，**并发重复请求只会成功一次**，其余返回错误 `2435`。

#### 错误响应

| 业务错误码 | message               | 说明                                                          |
|------------|-----------------------|---------------------------------------------------------------|
| `2400`     | `applyUid is required` | 缺少 `applyUid` 或小于等于 0                                  |
| `2401`     | `missing authorization token` | 未携带有效 Token，需重新登录                       |
| `2432`     | `target player not found` | 申请人玩家不存在                                          |
| `2435`     | `apply not found`      | 申请记录不存在（从未申请或已被处理，含并发重复请求）          |
| `2438`     | `friend count limit exceeded` | 好友数量已达上限（最多 100 个）                    |
| `2440`     | `friend operation failed` | 好友操作失败（如数据库异常）                            |
| `2500`     | `internal server error` | 服务端内部错误                                                |

## 收到的申请列表

### `GET /api/friend/apply/in`

获取当前玩家**收到**的申请列表（`targetUid` = 当前玩家），按创建时间倒序。列表**仅包含待处理申请**（同意/拒绝后记录即删除）。

#### 请求参数（Query String）

| 参数    | 类型  | 必填 | 说明                                                             |
|---------|-------|------|------------------------------------------------------------------|
| `start` | int32 | 否   | 起始位置（从 1 开始，闭区间），默认 `1`                          |
| `end`   | int32 | 否   | 结束位置（闭区间），默认 `start + 19`；`(1,20)` 表示查询前 20 条 |

> 分页规则见[分页规则](#分页规则)：单页上限 50，`start` 上限 101，返回 `hasMore`。

#### 成功响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "items": [
      {
        "applyUid": 100001,
        "targetUid": 100002,
        "nickname": "Alice",
        "level": 12,
        "createdAt": 1780000000000
      }
    ],
    "hasMore": false
  }
}
```

`data.items` 每项结构：

| 字段        | 类型  | 说明                                    |
|-------------|-------|-----------------------------------------|
| `applyUid`  | int64 | 申请人玩家 ID                           |
| `targetUid` | int64 | 被申请人玩家 ID（即当前玩家）           |
| `nickname`  | string | 对方玩家昵称                           |
| `level`     | int32 | 对方玩家等级                            |
| `createdAt` | int64 | 申请创建时间（Unix 毫秒）               |

| 字段      | 类型 | 说明                                    |
|-----------|------|-----------------------------------------|
| `hasMore` | bool | 是否还有更多                            |

> 幽灵过滤：申请人已不存在的申请不展示；`hasMore` 仍以数据库分页结果为准。

#### 错误响应

| 业务错误码 | message                     | 说明                         |
|------------|-----------------------------|------------------------------|
| `2400`     | `invalid request parameters` | 请求参数解析失败             |
| `2401`     | `missing authorization token` | 未携带有效 Token，需重新登录 |
| `2440`     | `friend operation failed`   | 好友操作失败             |
| `2500`     | `internal server error`     | 服务端内部错误               |

## 好友排行榜

### `POST /api/friend/rank`

获取当前玩家的好友排行榜（所有排行均在好友范围内），按**分数倒序**排列，同分按**玩家 ID 升序**排列；名次按位置**连续编号**（同分不共享名次）。排行榜**包含本人**。排行维度由 `type` 指定，接口按类型分派获取对应的排行榜内容，当前支持等级排行（Type=1，分数为玩家等级），后续新增排行维度时在 `RankType` 枚举中扩展。

请求体可通过 `friends` 传入**额外好友的第三方账号（account）列表**：服务端按 account 批量解析出对应玩家，与既有好友关系取并集后并入排行候选（自动去重，本人与已存在好友重复传入不会重复上榜）。该参数为空或不传时，行为与仅按好友关系排行完全一致；空账号、查不到的账号会被忽略；已注销的账号不参与解析；


#### 请求体

```json
{
  "type": 1,
  "friends": ["account_100002", "account_100003"]
}
```

| 字段      | 类型     | 必填 | 说明                                                         |
|-----------|----------|------|--------------------------------------------------------------|
| `type`    | int32    | 是   | 排行维度类型（`RankType` 枚举值，1=等级排行）                |
| `friends` | string[] | 否   | 额外好友的第三方账号（account）列表，服务端解析为玩家后并入排行

玩家身份由 Token 解析。

#### 成功响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "items": [
      {
        "rank": 1,
        "playerUid": 100002,
        "nickname": "ShadowBlade",
        "score": 45
      },
      {
        "rank": 2,
        "playerUid": 100001,
        "nickname": "Player_100001",
        "score": 30
      }
    ],
    "self": {
      "rank": 2,
      "playerUid": 100001,
      "nickname": "Player_100001",
      "score": 30
    }
  }
}
```

| 字段    | 类型   | 说明                              |
|---------|--------|-----------------------------------|
| `items` | array  | 排行榜列表（含本人）              |
| `self`  | object | 自己的排名（固定返回，不依赖 `items` 是否包含本人） |

`items[]` / `self` 元素（结构同为 `RankItem`）：

| 字段        | 类型   | 说明                          |
|-------------|--------|-------------------------------|
| `rank`      | int32  | 名次（从 1 开始，按位置连续编号） |
| `playerUid` | int64  | 玩家 ID（可能是本人）          |
| `nickname`  | string | 玩家昵称                      |
| `score`     | int32  | 排行分数（等级排行中为玩家等级） |

> 本人恒参与排行，即使暂无好友排行榜 `items` 也至少包含本人一条，且 `self` 始终返回自己的排名。

#### 错误响应

| 业务错误码 | message                     | 说明                         |
|------------|-----------------------------|------------------------------|
| `2400`     | `invalid request parameters` / `invalid rank type` | 请求参数解析失败或排行榜类型错误 |
| `2401`     | `missing authorization token` | 未携带有效 Token，需重新登录 |
| `2440`     | `friend operation failed`   | 好友操作失败（如数据库异常） |
| `2500`     | `internal server error`     | 服务端内部错误               |

## 删除好友

### `POST /api/friend/delete`

删除当前玩家与指定玩家的好友关系（双向删除）。不影响好友申请记录，删除后双方可重新申请。

#### 请求体

```json
{
  "friendUid": 100001
}
```

| 字段        | 类型  | 必填 | 说明           |
|-------------|-------|------|----------------|
| `friendUid` | int64 | 是   | 好友玩家 ID    |

#### 成功响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "friendUid": 100001
  }
}
```

| 字段        | 类型  | 说明               |
|-------------|-------|--------------------|
| `friendUid` | int64 | 被删除好友的玩家 ID |

> 幂等说明：删除已不存在的单向关系不会报错，接口仍返回成功；双向关系任意一侧已缺失时，另一侧会被正常删除。

#### 错误响应

| 业务错误码 | message                 | 说明                         |
|------------|-------------------------|------------------------------|
| `2400`     | `friendUid is required` | 缺少 `friendUid` 或小于等于 0 |
| `2401`     | `missing authorization token` | 未携带有效 Token，需重新登录 |
| `2440`     | `friend operation failed` | 好友操作失败（如数据库异常） |
| `2500`     | `internal server error` | 服务端内部错误               |

## 错误处理

### 错误码总览

| 业务错误码 | message                                     | 触发场景                                     |
|------------|---------------------------------------------|----------------------------------------------|
| `2400`     | `invalid request parameters` / 各参数 required | 请求参数缺失或非法                            |
| `2401`     | `missing authorization token`               | 未认证或 Token 失效，需重新登录              |
| `2430`     | `cannot add yourself as friend`             | 添加自己为好友                                |
| `2431`     | `already friends`                           | 目标已经是好友，无需再申请                    |
| `2432`     | `target player not found`                   | 目标/申请人玩家不存在                          |
| `2434`     | `apply already pending`                     | 同方向已存在申请（重复申请或并发冲突）        |
| `2435`     | `apply not found`                           | 申请记录不存在（从未申请或已被处理）          |
| `2437`     | `you already have an apply from this player` | 对方已向你发送申请，引导去收到的申请列表处理  |
| `2438`     | `friend count limit exceeded`                | 好友数量已达上限（最多 100 个）              |
| `2440`     | `friend operation failed`                   | 好友操作失败（数据库异常等系统问题）      |
| `2500`     | `internal server error`                     | 服务端内部错误                                |

### 客户端建议处理策略

| 错误码 | 处理方式                                                                                    |
|--------|---------------------------------------------------------------------------------------------|
| `2400` | 检查请求参数（如 `targetUid` / `applyUid` / `friendUid` 合法性），修复后重试               |
| `2401` | Token 失效，重新调用 `/auth/login` 获取新 Token 后重试                                      |
| `2430` | UI 上禁止选择自己为申请/删除目标                                                           |
| `2431` | 已互为好友：客户端可展示好友名片或引导直接进入聊天                                          |
| `2432` | 目标玩家不存在：提示"玩家不存在"，无需重试                                                  |
| `2434` | 同方向已有申请（重复发送或并发）：提示"已发送过申请"，或刷新申请列表                        |
| `2435` | 申请不存在（从未申请或已被处理）：刷新申请列表即可                                          |
| `2437` | 对方已向你发送申请：提示"对方已申请加你为好友"，引导到收到的申请列表处理                    |
| `2438` | 好友已满（最多 100 个）：提示"好友数量已达上限"，建议先清理部分好友再申请                |
| `2440` | 系统问题（操作失败）：弹出提示，提供"重试"按钮；可上报日志                                  |
| `2500` | 服务端内部错误：弹出提示，提供"重试"按钮；可上报客户端日志辅助排查                          |
| 网络错误（超时 / 无响应） | 检查网络后重试；`apply` / `handle` / `cancel` / `delete` 均为幂等或可重入，重复请求不会产生重复好友/重复申请 |
